Status
In progress
TypePRD

Product Vision

To empower restaurants of all sizes with a seamless, contactless ordering experience — where customers scan, browse, and order in seconds, staff stay focused on service, and owners get full visibility into their operations through a single, elegant platform.

Problem Statement

Traditional restaurant ordering is slow, error-prone, and staff-intensive. Printed menus go out of date. Waiters misplace orders. Customers wait too long. Restaurant owners have no real-time data on what's selling, what's slow, or where bottlenecks occur.

Existing solutions are either too expensive, too complex to set up, or too ugly to inspire confidence in a paying customer. There is a clear gap for a premium, fast, and simple QR-based ordering system tailored for the modern restaurant.

Goals

Business Goals

  • Demonstrate a working MVP to restaurant owners within the first sales cycle
  • Reduce onboarding time to under 30 minutes per restaurant
  • Target 10 paying pilot customers in the first 3 months

Product Goals

  • Cut average order time from ≥5 minutes to <90 seconds
  • Eliminate order transcription errors entirely
  • Give admins a real-time view of all active orders and table statuses

User Goals

  • Customers: order food without waiting for a waiter
  • Staff: receive orders instantly with no verbal communication errors
  • Owners: manage the full menu, tables, and staff from one dashboard

User Flow

End-to-End Customer Journey

  1. Customer Scans QR Code
    • Each table has a unique QR code printed on a card or stand
    • Customer opens phone camera and scans
    • No app download required — opens directly in mobile browser
  1. Menu Loads Instantly
    • Restaurant branding (logo, name, cover image) appears
    • Menu categories load in a horizontally scrollable tab bar
    • Featured or popular items appear at the top
  1. Customer Browses Categories
    • Taps a category (e.g. Starters, Mains, Desserts, Drinks)
    • Items display as cards: photo, name, short description, price
    • Tapping an item opens a detail view with full description, allergens, and customization options
  1. Customer Adds Items to Cart
    • Selects quantity, optional add-ons or notes (e.g. "no onions")
    • Taps "Add to Cart" — cart icon updates with item count
    • Can continue browsing and adding items
  1. Customer Reviews Cart
    • Cart screen shows all items, quantities, individual and total prices
    • Can edit quantities or remove items
    • Special instructions field available for the full order
  1. Customer Places Order
    • Taps "Place Order"
    • No login required for MVP — table is identified by QR code
    • Order confirmation screen shows order number and estimated wait time
    • Real-time status tracker appears: Received → Preparing → Ready → Served
  1. Kitchen Receives Order
    • Order appears instantly on the kitchen/staff dashboard
    • Displays: table number, items ordered, quantities, special notes, timestamp
    • Staff can mark order as "Preparing" and then "Ready"
  1. Waiter Serves the Order
    • Staff marks order as "Served" after delivering to table
    • Customer's tracking screen updates to "Served"
  1. Order Completed
    • Order is logged in history
    • Admin dashboard reflects completed order in analytics
    • Table status resets to available (or stays occupied until manually cleared)

Database Entities

Entity Map

Restaurant

  • id, name, logo_url, cover_url, currency, tax_rate, is_active, created_at
  • One restaurant has many Tables, Categories, Staff, Orders

Table

  • id, restaurant_id, table_number, label, qr_code_url, status (free/occupied), created_at
  • Belongs to Restaurant. Has many Orders

Category

  • id, restaurant_id, name, image_url, sort_order, is_active
  • Belongs to Restaurant. Has many Food Items

Food Item

  • id, category_id, restaurant_id, name, description, price, image_url, is_available, is_featured, sort_order
  • Belongs to Category. Appears in many Order Items

Order

  • id, restaurant_id, table_id, status (pending/preparing/ready/served/cancelled), special_instructions, total_amount, created_at, updated_at
  • Belongs to Table and Restaurant. Has many Order Items

Order Item

  • id, order_id, food_item_id, quantity, unit_price, notes
  • Belongs to Order and Food Item

Customer (optional in MVP — table-based ordering)

  • id, name, phone, email, created_at
  • Future: linked to Orders for loyalty

User (base auth entity)

  • id, name, email, password_hash, role (admin/staff), restaurant_id, is_active, created_at
  • One User per Staff or Admin account

Staff

  • id, user_id, restaurant_id, role (waiter/kitchen/manager)
  • Extends User with operational context

Payment (future)

  • id, order_id, amount, method, status, transaction_id, paid_at
  • Belongs to Order

Dashboard Modules

Admin Dashboard (/admin)

1. Live Overview Strip

Real-time counters: Active Orders | Tables Occupied | Today's Revenue | Orders Today

Updates every few seconds via polling or WebSocket.

2. Active Orders Feed

Live scrollable list of all in-progress orders. Each card shows table number, item count, elapsed time, and current status. Color-coded: yellow = preparing, green = ready.

3. Table Map

Visual grid of all tables. Color indicates: gray = free, yellow = order placed, green = order ready to serve.

4. Today's Top Items

Bar chart or ranked list of most ordered items today. Quick insight into what's driving revenue.

5. Revenue Chart

Line or bar chart showing hourly or daily revenue. Toggle between Today / This Week / This Month.

6. Recent Orders Log

Last 10 completed or cancelled orders with timestamp, table, and value. Links to full order history.

Design Guidelines

Philosophy: Premium restaurant experience — think Zomato meets Linear. Clean, fast, opinionated.

Theme

  • Light mode and dark mode supported from day one
  • Neutral base palette with a bold accent (e.g. amber or coral for food context)
  • System font stack with optional Google Font for headings

Layout

  • Mobile-first — all customer flows designed for 375px+ screens
  • Admin dashboard responsive — works on tablet and desktop
  • Max content width: 480px for customer, 1280px for admin

Components

  • Rounded cards with subtle shadows (rounded-2xl, shadow-sm)
  • Consistent 8px spacing grid
  • Smooth transitions: 200ms ease for modals, 150ms for buttons
  • Micro-interactions: cart icon bounce on add, status step pulse animation

Images

  • All food item images 16:9 or 1:1 aspect ratio, object-cover
  • Placeholder illustration for missing images (no broken images)

Typography

  • Heading: 24–32px bold
  • Body: 14–16px regular
  • Caption/meta: 12px muted
